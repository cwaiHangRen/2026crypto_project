# 数据集检索与选型记录

更新时间：2026-10-06

本文用于给 `gm-provenance` 的图片、PDF、内容凭证、数字签名和媒体水印基准选择公开数据源。本文记录的是网络检索与选型结论；在完成下载、文件解码、正文/元数据核对和逐文件许可证审计之前，不把任何数据集标记为已验证输入。

## 项目所需数据形态

项目需要覆盖以下输入：

- PNG/JPEG 等普通图片；
- 单页和多页 PDF；
- 文本、图片和混合布局；
- 真实来源与 AI 生成来源，用于生成 G0（无凭证/无水印）、G1（仅签名）、G2（仅水印）、G3（签名+水印）基准；
- 常见变换后的副本，用于验证恢复、派生版本、撤销状态和篡改处理；
- 可追溯的 `source_id`、来源 URL、下载时间、原始文件哈希、许可证证据和数据划分。

真实性标签只能表示数据集来源或生成方式，不能代替项目中的密码凭证验证。数据集本身也不能证明某个传输副本是真实发布版本。

## 候选数据集

| 数据集 | 适合角色 | 规模/内容证据 | 许可证与访问 | 与项目匹配度 | 主要限制 |
|---|---|---|---|---|---|
| [Open Images](https://github.com/openimages/dataset) | 真实图片主库 | 官方仓库记录约 900 万图片 URL、6000 多类，训练集约 900 万、验证集约 16.7 万；图像由唯一 64 位 ID 标识 | 标注为 CC BY 4.0；图像来自不同来源，官方明确要求逐图核验许可 | 高，适合真实图片、类别多样性和大规模哈希/签名样本 | 主要提供 URL 和元数据，链接会失效；不能把整库当成单一许可证 |
| [COCO](https://cocodataset.org/) | 可控的真实图片试验集 | 官方站点提供超过 20 万张图片、80 个类别和公开标注 | 必须遵守官方 Terms of Use，并保留原始来源信息 | 高，适合先做可重复的小规模试验和视觉内容覆盖 | 规模小于 Open Images；逐文件的来源与使用条款仍需记录 |
| [GenImage](https://github.com/GenImage-Dataset/GenImage) | AI 生成图片主库 | 官方项目说明超过 100 万真实/伪造图像对，覆盖 ImageNet 类别和 Midjourney、Stable Diffusion、ADM、GLIDE、Wukong、VQDM、BigGAN 等生成器 | 项目主页标注 CC BY-NC-SA 4.0；非商业使用，需保留署名和数据集条款 | 高，适合 G2/G3、生成器分层和跨生成器测试 | 非商业限制；需要核对原始来源、类别和生成器元数据；不能把检测标签当作密码凭证结论 |
| [DocLayNet](https://github.com/DS4SD/DocLayNet) | PDF 页面与混合布局主库 | 80,863 页人工标注，6 类布局，覆盖财务、科学、专利、招标、法律和手册等文档；提供 PNG、单页 PDF 和 JSON | 数据卡标注 CDLA-Permissive-1.0；应保留数据卡、原始文件和标注关系 | 高，适合 PDF 页面级水印、文本/图像混合和版面变换 | 配套 PDF 是单页页面，不能单独覆盖自然多页文档；多页样本需另取来源或明确标记为组合样本 |
| [PubLayNet](https://github.com/Machine-NO-Learning/PubLayNetDataset) | 科学文献 PDF 页面辅助库 | 来源为 PubMed Central Open Access Subset，提供 PDF 页面及 XML/PDF 生成的版面标注 | 单篇 PMC 文章的许可证可能不同，必须保留文章级许可和来源 URL | 中高，适合科学排版、图表、双栏和文本块 | 许可证不统一；页面/标注格式与当前项目内容凭证字段需要适配 |
| [arXiv bulk data](https://github.com/arXiv/arxiv-docs/blob/develop/source/help/bulk_data/index.md) | 真实多页 PDF 主库 | 官方文档支持通过导出、AWS、Kaggle 等方式获取 PDF/TeX 和元数据 | arXiv 明确要求遵守 API 条款、品牌规范和内容本身的许可证；应筛选 CC BY/公版等可再分发内容 | 高，适合真实多页 PDF、文档版本和正文核验 | 不是统一许可证；需要按论文记录 license、版本、标题/作者/DOI 和正文一致性 |
| [AIGCDetectionBenchmark](https://github.com/Ekko-zn/AIGCDetectBenchmark) | 外部 AI 图片压力测试 | 官方仓库提供多生成器测试集下载入口，并以 CNNSpot 等数据作为训练/对照来源 | 当前公开页面没有足够清晰的统一再分发许可，应先做逐文件审计 | 中，适合独立评估模型/规则是否跨生成器泛化 | 不建议直接作为项目主库；规模、许可和版本固定方式需要另行确认 |
| [UniversalFakeDetect](https://github.com/WisconsinAIVision/UniversalFakeDetect) | 跨 GAN/扩散模型压力测试 | 官方仓库提供约 19 个测试子集；扩散测试按域发布约千张级别样本，并有较大的训练集 | 官方页面未给出可直接采用的统一数据许可证 | 中，适合外部测试，不适合直接混入发布基准 | 数据量大、来源和许可审计成本高；应固定测试子集和下载版本 |
| [AI-GenBench](https://github.com/MI-BioLab/AI-GenBench) | 基准协议参考 | 官方仓库强调按时间顺序组织生成器，测试对新生成器的泛化能力 | 需按仓库当前版本和数据链接核对许可 | 中，适合设计“留出生成器”的评测协议 | 更适合参考评测方法；不应在未完成许可核验前作为主数据源 |

## 筛选结果

本轮筛选按五个项目因素判断：媒体覆盖、来源/元数据可追溯性、许可证清晰度、下载可重复性、与现有注册/签名/水印流程的接入成本。这里的等级是面向本项目的工程判断，不是对数据集学术质量的排名。

### A 级：建议纳入第一版数据方案

| 数据集 | 结论 | 选择理由 | 需要接受的边界 |
|---|---|---|---|
| COCO | **保留，作为真实图片试验主库** | 规模适中、类别稳定、容易固定版本和样本清单；适合先验证 G0–G3、签名、恢复、变换、撤销和 API 流程 | 必须保留官方 Terms of Use 和原始来源信息；不能把 COCO 当作统一许可证的数据包 |
| GenImage | **保留，作为 AI 图片主库** | 生成器类型多，能覆盖项目需要的 AI 来源、生成器分层和留出生成器测试 | CC BY-NC-SA 4.0 使它适合研究/非商业交付；必须保留生成器、类别和原始配对信息 |
| DocLayNet | **保留，作为 PDF 页面与混合布局主库** | 有人工版面标注，覆盖财务、科学、法律、手册等页面；适合 PDF 页面级水印和内容变换 | 配套 PDF 是单页，不能宣称覆盖自然多页文档；多页能力由筛选后的 arXiv 补足 |
| 许可证筛选后的 arXiv 子集 | **保留，作为真实多页 PDF 主库** | 能提供真实多页、正文、版本和作者/DOI 等信息，适合验证多页注册、父子版本和正文一致性 | 只纳入许可证明确的论文；按 `document_id` 划分，不能把同一论文不同页面拆到不同数据集分区 |

### B 级：保留为扩展或专项补充

| 数据集 | 结论 | 选择理由 | 暂不列入第一版主库的原因 |
|---|---|---|---|
| Open Images | **保留，作为规模扩展库** | 类别和规模都很大，适合后续扩大真实图片覆盖和压力测试 | 主要是 URL/元数据，链接可失效；逐图许可证和下载成功率审计成本高，不适合作为第一轮固定基线 |
| PubLayNet | **保留，作为科学 PDF 页面补充** | 科学论文版面、双栏、图表和文本块有价值 | PMC 文章许可证不统一；与 DocLayNet 的页面/标注格式需要适配 |

### C 级：不纳入主数据集，仅作外部评估

| 数据集 | 处理决定 | 理由 |
|---|---|---|
| AIGCDetectionBenchmark | 外部压力测试 | 适合检验跨生成器泛化，但当前公开页面对统一再分发许可和固定版本说明不足 |
| UniversalFakeDetect | 外部压力测试 | 测试子集多，适合独立比较，但训练规模和来源许可审计成本较高 |
| AI-GenBench | 评测协议参考 | 对“留出新生成器”有参考价值，但当前更适合作为方法和划分设计依据 |

## 最终保留清单

第一版只保留以下四类，避免数据源过多导致许可、版本和泄漏控制失焦：

1. **COCO**：真实图片的可重复小规模基线；
2. **GenImage**：AI 生成图片和跨生成器分层；
3. **DocLayNet**：单页 PDF、文本/图片混合和布局变换；
4. **许可证筛选后的 arXiv 子集**：真实多页 PDF 和版本链。

Open Images 和 PubLayNet 暂列扩展源；AIGCDetectionBenchmark、UniversalFakeDetect、AI-GenBench 不进入主清单。这个取舍的核心原因是：项目需要同时覆盖图片、AI 图片、单页 PDF 和自然多页 PDF，而没有一个数据集能够在媒体覆盖、版本稳定性和许可证清晰度上独立满足全部要求。

## 暂不采用的来源类型

暂不把没有逐文件许可证证据、只有不稳定 URL、无法固定版本、无法区分论文/原图/生成器边界，或把“AI 生成标签”直接当成真实性结论的数据源纳入主库。也暂不选用未经审计的超大规模网页抓取集合；它们会增加重复、链接失效、版权和数据泄漏风险，不能直接改善当前密码协议验证目标。

## 推荐组合

建议采用分层组合，而不是寻找一个同时覆盖所有媒体类型、生成器和多页文档的单一数据集：

1. **图片真实来源**：先用 COCO 做可重复小规模试验；扩大规模时加入 Open Images。两者都保留图片 ID、原始 URL、下载时间、逐文件许可证证据和内容哈希。
2. **AI 生成来源**：以 GenImage 为主，按生成器和类别分层，至少留出一个生成器作为跨生成器测试集。由于它标注为 CC BY-NC-SA 4.0，不应直接用于商业再分发。
3. **PDF 页面**：以 DocLayNet 为主，用于文本/图片混合页面、布局变化和单页 PDF；以 PubLayNet 补充科学文献版面。
4. **真实多页 PDF**：从 arXiv 中筛选许可证明确的论文子集，按论文而不是按页面划分训练/验证/测试，保留版本、标题、作者、DOI 和正文核对信息。
5. **外部压力测试**：AIGCDetectionBenchmark、UniversalFakeDetect 和 AI-GenBench 只作为独立外部评估或协议参考，先完成版本、下载入口和许可证审计，再决定是否纳入交付包。

## 建议的数据清单字段

每一个源文件至少生成一条不可变清单记录：

```json
{
  "dataset": "DocLayNet",
  "source_id": "dataset-native-id",
  "source_url": "https://…",
  "license": "CDLA-Permissive-1.0",
  "license_evidence_url": "https://…",
  "retrieved_at": "2026-10-06T00:00:00Z",
  "media_type": "application/pdf",
  "document_id": "optional-document-id",
  "page_no": 1,
  "split": "train|validation|test",
  "generator": null,
  "original_filename": "source-name.pdf",
  "sha256": "computed-after-download",
  "sm3": "computed-after-download",
  "bytes": 0,
  "decode_status": "pending|pass|fail",
  "license_status": "pending|pass|review|reject"
}
```

`sha256` 用于和外部下载记录对照，`sm3` 用于项目内容凭证；在文件真正下载前不要预填哈希。对 PDF 要额外记录 `%PDF` 头、页数、首页面文本/标题以及必要时的作者/DOI；对图片要记录解码尺寸、颜色模式和是否被重新编码。

## 下载和验收顺序

1. 先下载一个小型试验集：每个候选源 50–100 个图片或页面，另外准备少量明确许可的多页 PDF。
2. 对每个文件做字节级哈希、重复检测、图片解码或 PDF `%PDF`/页数检查，并把失败文件保留在失败清单中。
3. 核对数据集原生 ID、来源 URL、许可证证据和文件正文；不要仅凭扩展名、HTTP 200 或数据集名称判定有效。
4. 以 `source_id`、论文 `document_id` 或生成器为边界划分数据集，避免同一论文的页面、同一原图的不同变体或同一生成器的近重复跨越训练与测试。
5. 将项目自己生成的 G0–G3、裁剪、缩放、重编码和模拟攻击记录为派生样本，不能把派生样本误写成外部数据集原始标签。
6. 下载通过后再把清单输入现有注册、签名、恢复、变换、撤销和 API 联调流程；先做 1000 样本级别的可复现实验，再扩展规模。

## 当前结论与待核验项

当前最符合项目需求的第一版组合是：**COCO + GenImage + DocLayNet + 许可证筛选后的 arXiv 多页 PDF**。Open Images 和 PubLayNet 作为扩展源，三个 AI 检测基准作为外部压力测试。这个组合覆盖图片、AI 生成图、单页 PDF、混合版面和真实多页 PDF，同时能把来源标签与项目的密码学真实性判断分开。

小样本下载和初步联调结果见 [DATASET_PILOT_RESULTS.md](DATASET_PILOT_RESULTS.md)；本轮没有下载任何完整外部数据集，也没有声称完成逐文件许可证核验。后续应先对最终四类的原始数据入口固定版本、拆分规则和许可证据，再决定是否扩展到完整规模。
